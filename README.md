# dashhq.org

The front door and directory for the Dash ecosystem. Static HTML, CSS and JavaScript; no build dependencies or backend.

`index.html` opens with the headline, the lede and the search, then the connected three-tier ecosystem map at the full content width, then four task cards. The map holds only the main projects (11); everything else lives in `/directory/`, which the map's header link and its closing primary button open. Every map node names its maintainer. The map uses four columns on desktop and tablets, with amber funding wires on desktop, and two columns below 680 px. A search that matches nothing on the map leaves the map undimmed. Search results carry a layer tile and also highlight matching projects in place. A compact Mainnet observation line keeps its live source beside the figures. `/directory/` lists all 70 projects and resources as cards in tinted category bands, four across from 1400 px, with a description, maker, status and monospace host for each. Network tags come from the catalog; docs, diagrams and source libraries use descriptive status tags. Each card's tile, in its layer colour, holds the project's own mark where it has a distinctive one (`icons/brands/`, fetched once and self-hosted) or a line icon from `icons/directory.svg` (24 px grid, 1.8 stroke, drawn in the tile's ink). Home search results reuse the same tile. Map links open their directory entries. `/identity/` explains sign-ins and key handling.

`hub.js` searches the inert `#directory-index` template without hiding the page. Keep that template in sync with `/directory/` when editing resources. Search handles public ProTx hashes, IPs, Platform IDs and bare or suffixed Dash names, with task-specific routes for treasury, fees, voting and polls. Store and guide links stay within their resource result. Escape clears the field. The directory reuses the same matching, with counts, a clear button, a query URL and category anchors in a single scrolling strip that also works without JavaScript. Without JavaScript the finder stays hidden; every visible destination remains a normal link.

`pulse.js` reads Radar’s public Mainnet summary with a bounded timeout and five-minute refresh. It shows observation age, stale-data warnings and retry on failure. Counts and source details remain available through the adjacent snapshot link and metric titles. No other data service is contacted. Fonts and assets are local, and CSP permits no inline scripts or styles.

The shell is pinned under `dashhq/`; see `SHELL.md`. The hub has a text wordmark and a local lowercase d favicon. Yappr, Forge, EvoVote and Pollr are outbound links; the Fee estimator opens fees.dashhq.org, and explorer.dashhq.org is Radar Explorer.

Local checks: `node --check hub.js` and `node --check pulse.js`. The browser checks live with the family lab (`lab/hub-qa.mjs`). Pages serves this directory as it is, so keep lab notes and scripts out of it; the one exception is the Dash Sites deploy tooling (`scripts/`, `DEPLOY.md`), which holds nothing secret. There is no package-managed lint, typecheck or unit-test suite. Build with `lab/build.sh hub` from the lab root, then use the guarded screenshot runner.

A compact copy of the site is also published to the Dash Platform name `d4shhq` (https://d4shhq.dash.site) by `.github/workflows/dash-site.yml`. Pages is unaffected. See `DEPLOY.md`.
